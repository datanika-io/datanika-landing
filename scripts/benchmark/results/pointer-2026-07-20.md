# Benchmark Results — pointer.gr (shared VPS)

> ⚠️ **NOT a representative benchmark — do not cite this number.** This run executed on the
> **pointer.gr production VPS**, a **shared box** (it also runs the live `app.datanika.io` plus a
> co-tenant VPN/webdav) with markedly slower write IO than a dedicated instance. The full sync here
> is **2192s (~36.5 min)** vs the dedicated Hetzner CPX32's **571s** in
> [`cpx32-2026-04-16.md`](cpx32-2026-04-16.md) — **~3.8× slower**, driven by the shared disk +
> daytime contention, **not** by Datanika.
>
> This file exists to (a) document the run for the record (directed 2026-07-20, since the CPX32 box
> was decommissioned) and (b) prove the harness reproduces on current infra after the
> `requirements.txt` fix (`dlt[sql_database]` was missing → `benchmark.py` failed to import on
> dlt 1.29). **The blog's representative number remains the CPX32 dataset.** A fresh representative
> benchmark needs a *dedicated* box (deferred — no new-host spend pre-10-paid customers).

**Date**: 2026-07-20 15:56 UTC
**Host**: pointer.gr Gold VPS (Athens, 4 vCPU / 8 GB, Ubuntu 22.04) — **shared with prod**
**Workload**: 10,100,000 rows (customers + orders + line_items)
**Source**: PostgreSQL 16 (Docker, mem-capped 1.5 GB) → **Destination**: DuckDB (local file)
**Runner**: `benchmark.py --runs 3`, containerized + mem-capped (3 GB) so prod was unaffected — prod stayed `200` throughout, no OOM.
